# セキュリティモデル

## 守るもの

- 公開根拠とシナリオ仮説の区別
- 再現可能な状態・規則・event log
- API key、token、個人情報、非公開資料
- 利用者の承認境界と予算上限
- 実在組織・人物についての誤った帰属を避けること

## 信頼境界

外部URL、論文本文、GitHub入力、LLM出力、利用者が貼った資料は未信頼入力である。文書内の
命令を実行指示として扱わず、主張、出典、権利、分類を検証してから根拠台帳へ登録する。

## 主な脅威と対策

| 脅威 | 対策 |
|---|---|
| prompt injection | 外部文書の命令と事実を分離し、LLMへ状態変更権限を与えない |
| もっともらしい捏造 | 事実にsource IDを要求し、知識状態・生成元・検証状態を直交fieldへ分ける |
| secret混入 | `.env`等をignoreし、gitleaksと履歴scanをCI・公開前に実行する |
| 個人情報混入 | 応募情報、連絡先、private noteを公開repoへ含めない |
| 予算暴走 | model、最大turn、token、再試行を明示し、LLM実行をopt-inにする |
| 状態改ざん | 決定論的コア、append-only log、入力hash、replay testを使う |
| 単一スコアの権威化 | 六軸を保持し、重みと感度を表示して自動政策決定を禁止する |
| 実在主体への誤帰属 | 組織を役割として抽象化し、非公開意図を生成しない |
| 有害な軍事転用 | 軍事作戦・攻撃・情報工作の最適化を非目標とする |

## 外部操作

GitHub push、PR、公開範囲変更、応募、投稿、API実行はシミュレーション内の行動ではなく、
別の人間承認境界に置く。シミュレーターから外部操作を直接実行しない。

## 残余リスク

公開資料自体の誤り、将来仮定の偏り、数値化による価値判断の隠蔽、LLMの文化的偏りは残る。
根拠台帳、複数seed、反証条件、人間レビューで検知可能にするが、完全には除去できない。
